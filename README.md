# Калорийность блюд

Полностью офлайн Android-приложение: наводите камеру на этикетку продукта — OCR распознаёт состав, приложение считает калории и БЖУ блюда. Разрешение `INTERNET` в манифесте отсутствует, данные не покидают устройство.

## Возможности

- список блюд; в блюде — продукты с весом и итоговые калории/БЖУ;
- добавление продукта тремя способами: сканирование этикетки камерой, выбор из справочника, ввод вручную;
- распознавание этикеток (Tesseract OCR, языки rus+eng, модели tessdata_fast);
- парсер этикеток понимает форматы: «Белки 12,5 Жиры 5,0 Углеводы 60,0», «Б/Ж/У: 10/5/60», «б 10 ж 5 у 60», табличные макеты, кДж (пересчёт в ккал /4.184), запятую и точку как десятичный разделитель, латинские двойники кириллических букв;
- автоматически пополняемый справочник продуктов (имя + БЖУ на 100 г);
- расчёт: заявленная калорийность на 100 г, а если не указана — 4·Б + 4·У + 9·Ж.

## Требования

- Android Studio (Koala или новее), Android SDK 34;
- полный JDK 17+ (проверено на Java 21): нужен `jlink` из JDK — JRE не подойдёт.

## Сборка

Локальная сборка без Android Studio (как на этой машине):

```bash
JAVA_HOME=~/tools/jdk-21.0.13+9 ./gradlew assembleDebug
```

Готовый APK: `app/build/outputs/apk/debug/app-debug.apk`. Юнит-тесты: `./gradlew testDebugUnitTest`.
Если `JAVA_HOME` указывает на полный JDK глобально, префикс не нужен.

1. Скачайте модели OCR (обязательно до первого запуска сканирования):

   ```bash
   ./scripts/download-tessdata.sh
   ```

   Модели кладутся в `app/src/main/assets/tessdata/` (rus ~3.9 МБ, eng ~4.1 МБ). Приложения копирует их в `filesDir/tessdata` при первом распознавании.

2. Откройте проект в Android Studio и синхронизируйте Gradle. Файл `gradle/wrapper/gradle-wrapper.properties` настроен на Gradle 8.9; jar-обёртки в репозитории нет — Android Studio скачает дистрибутив сама. Либо с локальным Gradle: `gradle wrapper --gradle-version 8.9`, затем `./gradlew assembleDebug`.

3. Tesseract4Android берётся с JitPack: `cz.adaptech.tesseract4android:tesseract4android:4.9.0` (репозиторий `https://jitpack.io` уже прописан в `settings.gradle.kts`).

## Структура

- `app/src/main/java/ru/labelcalc/data/Database.kt` — Room: блюда, позиции блюда, справочник продуктов;
- `app/src/main/java/ru/labelcalc/logic/CalorieMath.kt` — расчёт калорий;
- `app/src/main/java/ru/labelcalc/ocr/` — Tesseract-обёртка, подготовка изображения (downscale 2048, EXIF-поворот, ч/б), парсер этикеток;
- `app/src/main/java/ru/labelcalc/ui/` — Compose-экраны, навигация, тема;
- `app/src/test/` — юнит-тесты парсера и математики (`./gradlew test`).

## Ограничения

- OCR инициализируется заново на каждый снимок (~1–2 с); для ускорения можно переиспользовать один `TessBaseAPI`;
- парсер эвристический — распознанные значения всегда можно поправить на экране продукта, там же виден сырой текст OCR;
- сырой текст последнего сканирования хранится в памяти (`ScanCache`) и сбрасывается при ручном добавлении/выборе из справочника;
- при включённой обфускации нужен `app/proguard-rules.pro` (keep-правила уже добавлены).
